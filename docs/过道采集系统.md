# 过道采集系统（PowerBank + Deposit）

## 基本信息
- 功能定位：统一管理 highway（过道）资源采集，覆盖 PowerBank 与 Deposit 两类任务。
- 设计模式：统一发现管线（Observer 扫描）、双任务模型（`mine/power` + `mine/deposit`）、阶段化执行（建档→孵化→收尾）。
- 运行节奏：发现在 `UpdateHighwayScan()`；执行在 `UpdateMineMission()`。
- 数据边界：任务都落在 `mine` 任务池，分别使用 `PowerMineTask` 与 `DepositMineTask`。

## 统一发现流程
1. Observer 按 `OUTMINE_CONFIG.LOOK_INTERVAL` 轮询过道房间。
2. 若开启 `outminePower`：
- 用 `PowerBankCheck` 判断是否值得采集。
- 通过 `PowerMineMissionData` 计算编队规模与 boost 档位。
- 新建 `mine/power` 任务。
3. 若开启 `outmineDeposit`：
- 用 `DepositCheck` 判断可采点与可站位。
- 生成 `mine/deposit` 任务（含 `num/active`）。
4. 发现阶段带去重：同目标房已有同类型任务则不重复建档。

## PowerBank 执行流程（`handlePowerMine`）
1. 维持攻坚对：`power-attack + power-heal`。
2. 需要时补 `power-ranged`。
3. PB 进入收割阈值后补 `power-carry` 回收。
4. PB 消失或完成后自动清任务。

## Deposit 执行流程（`handleDepositMine`）
1. 周期复核目标房 Deposit 状态（冷却/可采性），失效即删任务。
2. 按 `num` 维持 `deposit-harvest` 数量。
3. 同步维持 `deposit-transfer`（通常按采集人数的 1/2 配比）。
4. `active=false` 时保留任务但暂停孵化，等待后续恢复或清理。

## 角色协同
- PowerBank：`power-attack/power-heal/power-ranged/power-carry`。
- Deposit：`deposit-harvest/deposit-transfer`。

## 当前实现边界
- 价值评估主要是规则阈值，不做市场收益实时优化。
- 依赖 Observer 可见性，未观测到的过道房无法即时建档。
