# 终端与市场系统

## 基本信息
- 功能定位：把“跨房资源发送”与“市场交易（挂单/Deal）”拆分治理，兼顾稳定性与收益。
- 设计模式：任务执行分层（`ResourceManage` 下发 send 任务，`TerminalWork` 执行发送）、策略引擎（`AutoMarket`）、缓存加速（市场 tick 缓存）。
- 运行节奏：`TerminalWork` 周期执行；`autoMarket` 按 `AUTO_MARKET_CONFIG.tickInterval` 执行。
- 数据边界：发送任务在 `missionPools.terminal`；市场策略配置在 `AutoMarketData`。

## Terminal 发送链路
1. 从 terminal 池领取 `send` 任务（`getSendMission`）。
2. 计算可发送量（资源量、能量手续费、终端冷却）。
3. 成功发送后扣减任务 amount；完成则删除任务。
4. 参数非法或不可执行任务会被清理，避免死任务。

## AutoMarket 策略链路
1. 读取房间自动市场配置并注入默认规则（能量买卖 + 采矿产物卖出）。
2. 按策略类型执行：
- `buy/sell`：创建/调价/扩单。
- `dealbuy/dealsell`：直接撮合市场现单。
3. 选单时综合价格、距离、传输成本，计算“有效单价”。
4. 对能量交易会特殊处理手续费，避免净收益为负。

## 关键设计细节
- 订单操作全量走缓存索引（`findMyOrderCached/getAllOrdersCached`）减少 CPU。
- 支持限价与最小调整幅度，避免频繁小幅调价。
- 能量有“跨房平衡优先”判断，防止市场行为干扰内部补给。

## 当前实现边界
- 当前策略为规则驱动，不含历史收益回测与动态风险模型。
- 不同 shard 的市场协同仍需通过更高层策略统一调度。
