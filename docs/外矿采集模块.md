# 外矿采集系统

## 基本信息
- 功能定位：在本地房间稳定后，自动维持外矿（能源矿、中央九房）采集、防御、搬运与道路建设。
- 设计模式：分阶段流水线（侦查→防御→预定→采集→搬运→建设）、反馈控制（按在场 creep + spawn 队列动态补员）、策略切换（`mode + QoS`）。
- 运行节奏：入口 `Room.outMine()`，在房间执行流中周期调用；不同模式下有不同扫描间隔。
- 数据边界：目标房配置来自 `OutMineData`；实时数量来自 `creepTickIndex` 与任务池统计。

## 主流程
1. 全局门禁：战争态、房间防御态、QoS 紧急态直接短路。
2. 经济门禁：能量低/核心孵化积压时，清理外矿经济角色孵化任务并暂停外矿。
3. 能源外矿 `EnergyMine()`：按间隔轮询目标房，执行侦查、防御、采集、搬运、建路。
4. 中央九房 `CenterMine()`：类似流程，但增加 Source Keeper/中央房专属逻辑。

## 角色与调度策略
- 侦查：`scout` 保证目标房可见。
- 防御：`out-defend` 或双人组 `out-2attack/out-2heal`。
- 生产：`out-harvest`、`reserver`、`out-mineral`、`out-build`。
- 搬运：`out-car/out-carry`，并在 high/rush 下启用激进小体型链路策略。

## 关键设计细节
- 先采后运：若目标房无有效 `out-harvest`，会清理该目标房的搬运孵化任务，避免空转。
- 搬运接力：判定照搬参考实现 参考实现 的 `getRelayTarget`，**不用几何推算**。三条闸门：
  ① **正面对穿**——双方互为对方本 tick 的移动意图目标格（BetterMove `isSwapIntent`）。
  引擎不允许两只 creep 同 tick 交换位置，所以这种队形两边都走不动，接力就是把死结解开；
  并排同行、同向超越都天然不成立，不需要额外排除。
  ② **航向相反**——返程（deliver）的一方是供给方，外出（collect）的一方是接收方；
  航向取自 out-carry 解析出的模式，相同就不接。
  ③ 货能一次装进接收方：整仓交空（且接收方到手后够半仓）、或一次把接收方填满。
  命中后交接货物，整仓交空时交换双方 `Memory.creeps`，并把方向锁写进双方 memory，
  使这一方当 tick 就按新身份上路（能量因此一 tick 前进两格）。
- 接头时机：**先移动登记意图、再尝试接头**（`moveOutCarryTo` 内）。顺序不能反——
  接头判据要求自己本 tick 已登记意图；接上后这一笔会被立刻作废、按新方向重登记。
- 接力频次：不设「一只 creep 每趟只准接一次头」这类刹车。**接力的价值是解对穿死结**：
  单线走廊（一格宽、无法侧身）里关掉接力，吞吐直接掉到 0（整条走廊堵死）；
  开阔地形里也值 +70% 左右（省掉侧身绕行的来回）。
  另外只加一道同对冷却：同一对 creep 6 tick 内不再互接，纯省 CPU、不影响吞吐
  （拥堵时两只 creep 会被车队反复顶成对穿，实测吞吐不变而接力次数减半）。
  冷却记录必须放堆（`global.__relayPairCooldown`）而非 Memory——完全交接会整体交换
  `Memory.creeps`，写在 memory 里的记录换手一次就被抹掉（实测冷却会完全失效）。
- 运输估算：基于房间线性距离、源数量、体型容量估算目标搬运数量。
- 路况感知：道路覆盖率达标时切换低 MOVE 体型，提高吞吐比。
- 优先级纠偏：外矿经济角色优先级会被下限保护，避免挤占本地核心角色。

## 与其它系统协作
- 与 Spawn 系统：通过 `SpawnMissionAdd` 下发角色任务。
- 与 QoS：在 constrained 模式降频运行可视化、建路与部分逻辑。
- 与防御系统：目标房有威胁时优先防御，不继续经济孵化。

## 当前实现边界
- 当前仅覆盖单 sourceRoom 视角调度，跨 shard 外矿需要走扩张/跨 shard 模块。
- 目标房异常场景（长期不可见）依赖侦查恢复，不做离线预测。
