# 外矿采集系统

## 基本信息
- 功能定位：在本地房间稳定后，自动维持外矿（能源矿、中央九房）采集、防御、搬运与道路建设。
- 设计模式：分阶段流水线（侦查→防御→预定→采集→搬运→建设）、反馈控制（按在场 creep + spawn 队列动态补员）、策略切换（`mode + QoS`）。
- 运行节奏：入口 `Room.outMine()`，在房间执行流中周期调用；不同模式下有不同扫描间隔。
- 数据边界：目标房配置来自 `OutMineData`；实时数量来自 `creepTickIndex` 与任务池统计。

## 主流程
1. 全局门禁：战争态、房间防御态、QoS 紧急态直接短路。
2. 经济门禁：中心房（SK）在母房能量低/紧急时暂停；**能量外矿目标房与预算不随母房能量状态砍单**——
   外矿是摆脱能量短缺的收入投资，砍它会形成「短缺 → 砍外矿 → 更短缺」的贫困陷阱。
   能量平衡由两处内建：预算公式本地编制优先占满 spawn（`getLocalSpawnReserve`）；
   孵化端 `out-harvest / out-carry` 纳入紧急降档（`spawnControl.EMERGENCY_DOWNSIZE_ROLES`），
   能量不足时按当前能量出小体型继续跑，而不是干等满仓。
3. 能源外矿 `EnergyMine()`：按间隔轮询目标房，执行侦查、防御、采集、搬运、建路。
4. 中央九房 `CenterMine()`：类似流程，但增加 Source Keeper/中央房专属逻辑。

## 角色与调度策略
- 侦查：`scout` 保证目标房可见。
- 防御：`out-defend` 或双人组 `out-2attack/out-2heal`。
- 生产：`out-harvest`、`reserver`、`out-mineral`、`out-build`。
- 搬运：`out-car/out-carry`，并在 high/rush 下启用激进小体型链路策略。

## 补员派单：先近后远 + 负载均衡
- **派单顺序**（`externalScheduler.sortOutMineSpawnTargets`，`ExternalMineSpawner.orderTargetsForSpawn`）：
  ① 源房→目标房线性距离升序（先近后远，近房收益回收更快）；
  ② 该目标房在 spawn 池里已挂的外矿经济任务数升序（挂单少的先派）；
  ③ 房名字典序（顺序稳定可复现）。`runEnergy`/`runCenter` 都按这个顺序补员。
- **单房挂单上限**（按角色分列：采集 `OUTMINE_HARVEST_PENDING_CAP = 2`、搬运 `OUTMINE_CARRY_PENDING_CAP = 3`）：
  外矿体型很大（RCL8 搬运工 48 格 ≈ 144 tick 孵化），单房一次把定编全塞进队列，
  就会独占总 spawn 数百 tick，其它外矿房一个 creep 都排不上；等终于轮到它们时
  又是一次性批量产出（采集/搬运同时到位 → 结构失衡 + 大批量干等）。
  设上限后队列随打随补，在多房之间自然轮转。
  采集与搬运**额度独立**：采集工定编小又是搬运的前置，绝不能被搬运队列堵住
  （否则采集断档后要等一整个搬运孵化周期才补得上）。
  「额度」只统计采集/搬运，防御/侦查/预定是临时任务不占额度，
  否则一次入侵就会把外矿补员整体卡死。
- **采集与搬运同层排队**（`OUTMINE_PIPELINE_LEVEL = RoleData['out-harvest'].level`）：
  spawn 取任务口径是「取全池最低 level」。若采集/搬运各用自身等级
  （`out-harvest=12 / out-carry=15`），孵化端会先把全帝国排队中的采集工孵完，
  才轮得到第一个搬运工——容器被挖满、搬运工迟迟不到位，两头一起干等。
  同层之后两者按入队先后轮流孵化（同房入队顺序即 采集→搬运）。
- **挂单是「重铺」而不是「追加」**（`ExternalMineSpawner.clearPlannedEconomyMissions`）：
  `runEnergy` / `runCenter` 在按序补员前，会先把自己源房名下的外矿**计划型**任务
  （`OUTMINE_PLANNED_ROLE_SET`：采集/搬运/建造/矿工）整体从池里作废，再按当前需求重下一遍。
  原因：上限判定读的就是这个池，只追加不清理时旧挂单会把额度永久占满——
  线上曾出现池里积压 **165 条**、其中约 77 条是早期启动阶段产生的 `level=15` 搬运工，
  它们比采集工（同层化后为 12）优先级更高，导致采集工一条都排不上、外矿整体停摆。
  每次调度按当前需求重铺后，顺序即「先近后远 + 挂单少者先派」，且不会残留。
  一次性任务（`out-defend`/`out-attack`/`reserver`/`scout`）与本地角色**不动**，
  别的源房写在同一个池里的任务也不动（判定见 `externalScheduler.shouldDropPlannedMission`）。
- 纯决策逻辑集中在 `modules/features/external/externalScheduler.ts`（`sortOutMineSpawnTargets` /
  `countPendingMissions` / `pickBestCarryRoomName` / `shouldDropPlannedMission`），取数（`Game.map`/任务池/视野）
  留在 `externalMine.ts` 适配层，便于单测覆盖（`test/externalMineSpawn.test.ts`）。

## 搬运工动态选房
- 搬运工不再死绑孵化时的 `targetRoom`：**参考实现里搬运工是母房级共享池**，
  谁积压多就去谁那儿；本实现不改孵化结构，补上等价能力。
- `ExternalMineAnalysis.pickBestCarryTargetRoom`（评分在 `pickBestCarryRoomName`）：
  按「这一趟能不能装满」为主评分，超出一次载量的积压给小加成，按线性距离收就近惩罚；
  已站在候选房里视为在途、不再收距离惩罚。只在同类目标房之间重平衡
  （能量外矿 ↔ 能量外矿、中心房 ↔ 中心房），避免搬运工被送进 SK 中心房。
- 各托管房的可用积压按 **源房 + tick 缓存**（`outmine_room_backlog`），
  同房多个搬运工复用同一份结果，不逐 creep 重算。
- 触发点（`out-carry.ts` 的 `maybeRebalanceCarryTargetRoom`）：
  ① 未锁定房内取货目标时（空仓出发 / 返程续航）重新评估；
  ② 「大批量干等」逃逸口——挤在同一个空容器口等填装时允许改房。
  已锁定目标则先打完这一单再评估，避免半途弃单。
- 抑制抖动：滞回余量 `CARRY_ROOM_SWITCH_MARGIN = 0.25` + 每 creep 换房冷却 40 tick。
  换房时房内取货缓存与「已预约源点」全部作废，避免把旧房的容器 ID 带进新房。

## 关键设计细节
- 先采后运：若目标房无有效 `out-harvest`，会清理该目标房的搬运孵化任务，避免空转。
- 搬运接力：判定基础照搬参考实现 的 交接判定（**不用房间名几何推算**），并扩展出
  「反向相遇」的两种队形，任一成立即可换手：
  ① **正面对穿**——双方互为对方本 tick 的移动意图目标格（BetterMove `isSwapIntent`）。
  引擎不允许两只 creep 同 tick 交换位置，所以这种队形两边都走不动，接力就是把死结解开；
  ② **平行擦肩**——相邻车道上反向错身（谁也不挡谁）：双方步进向量相反（点积 < 0），
  且接收方站在供给方「朝母房那一步」的正前方（投影 ≥ 1，货物落到接收方身上才会净前进一整步）。
  并排同列（投影 = 0，原地倒手白掉头）、已经错开往回走（< 0，货物倒退）、
  同向跟随（步进点积 > 0）、垂直穿越（= 0）、原地等待（无步进）都天然不成立，不需要额外排除。
  ③ **航向相反**——返程（deliver）的一方是供给方，外出（collect）的一方是接收方；
  航向取自 out-carry 解析出的模式，相同就不接。
  ④ 货能一次装进接收方：整仓交空（且接收方到手后够半仓）、或一次把接收方填满。
  命中后交接货物，整仓交空时交换双方 `Memory.creeps`，并把方向锁写进双方 memory，
  使这一方当 tick 就按新身份上路（能量因此一 tick 前进两格）。
- 接头时机：**先移动登记意图、再尝试接头**（`moveOutCarryTo` 内）。顺序不能反——
  接头判据要求自己本 tick 已登记意图；接上后这一笔会被立刻作废、按新方向重登记。
- 接力频次：不设「一只 creep 每趟只准接一次头」这类刹车。**接力的价值是解对穿死结 + 让货物
  在走廊里跳跃前进**：单线走廊（一格宽、无法侧身）里关掉接力，吞吐直接掉到 0（整条走廊堵死）；
  开阔地形里也值 +70% 左右（省掉侧身绕行的来回）。擦肩分支实测：吞吐持平略升（+2.5%），
  接力次数变多（每次 = 一次引用交换 + 意图作废，CPU 很轻），车队会自发分工成「中段接力节点」
  ——部分 creep 不再走完全程，靠中段换手把能量接力送回家。
  另外只加一道同对冷却：同一对 creep 6 tick 内不再互接，纯省 CPU、不影响吞吐
  （拥堵时两只 creep 会被车队反复顶成对穿，实测吞吐不变而接力次数减半）。
  冷却记录必须放堆（`global.__relayPairCooldown`）而非 Memory——完全交接会整体交换
  `Memory.creeps`，写在 memory 里的记录换手一次就被抹掉（实测冷却会完全失效）。
- 运输估算：基于房间线性距离、源数量、体型容量估算目标搬运数量。
- 路况感知：道路覆盖率达标时切换低 MOVE 体型，提高吞吐比。
- 优先级纠偏：外矿经济角色优先级会被下限保护，避免挤占本地核心角色。

## 与其它系统协作
- 与 Spawn 系统：通过 `SpawnMissionAdd` 下发角色任务。
- 与 QoS：在 constrained 模式降频运行可视化、建路与部分逻辑。
- 与防御系统：目标房有威胁时优先防御，不继续经济孵化。

## 当前实现边界
- 当前仅覆盖单 sourceRoom 视角调度，跨 shard 外矿需要走扩张/跨 shard 模块。
- 目标房异常场景（长期不可见）依赖侦查恢复，不做离线预测。
