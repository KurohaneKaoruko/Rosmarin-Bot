# 主动防御系统

## 基本信息
- 功能定位：在敌对单位入侵时，统一完成威胁评估、防御状态切换、守军孵化、阵地选择与安全模式触发。
- 设计模式：分层防御（状态层/孵化层/塔防层）、威胁评分状态机（`observe/hold/breached`）、缓存化路径场（CostMatrix 签名缓存）。
- 运行节奏：`activeDefense()` 周期执行（默认每 5 tick）；与 `TowerWork()` 协同。
- 数据边界：核心状态落在 `room.memory.defend/defendUntil/defenseState/defenseRamparts/resourceUnsafeUntil`。

## 核心流程
1. 预检查：安全模式中直接返回；无威胁则清理防御孵化任务并退出防御态。
2. 威胁评估：统计敌方攻击/远程/治疗/boost 强度，刷新 `defendUntil`。
3. 防线分析：构建或复用防御 CostMatrix，判断是否已被突破（`breached`）。
4. 守军编成：按威胁类型与资源条件决定 `defend-attack/defend-ranged/defend-2attack/defend-2heal`。
5. 安全模式：关键建筑已损且高危威胁满足条件时触发 `activateSafeMode()`。

## 关键机制
- 防御点位选择：从高血量 rampart 中筛出近战/远程候选位写入 `defenseRamparts`。
- 资源入场保护：有威胁时延长 `resourceUnsafeUntil`，阻止跨房即时补资被敌方夺走。
- 双人组策略：仅在高强度威胁且 boost 条件满足时启用，避免常态高成本出兵。
- CostMatrix 优化：通过结构签名与多层缓存减少重复计算 CPU。

## 与塔防的协同
- 防御系统负责“是否防御、怎么防御、出什么兵”。
- 塔防系统负责“当前 tick 打谁/奶谁/修哪”，并读取防御态限制修塔行为。

## 当前实现边界
- 威胁评分仍是经验权重模型，不是战斗仿真最优解。
- 高压场景下若 QoS/CPU 紧张，会降级部分重计算逻辑。
