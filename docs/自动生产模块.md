# 自动生产功能

## 基本信息
- 功能定位：自动为 Lab/Factory/PowerSpawn 选择任务、投料、执行与收口，维持持续生产。
- 设计模式：策略层与执行层分离（Auto* 负责任务选择，StructureControl 负责执行）、状态机（空闲/执行/等待超时/结束）、回压控制（缺料等待与超时回收）。
- 运行节奏：由 `Room.exec()` 调度，按模块各自 tick 间隔运行。
- 数据边界：运行开关与目标写入 `StructData`；自定义任务写入 `AutoLabData/AutoFactoryData/AutoPowerData`。

## 模块拆分
- `autoLab`：选择合成任务（自定义优先，后备 T1/T2/T3），写入 `labAtype/labBtype/labAmount`。
- `LabWork`：按 A/B 基底 lab 运行反应；非基底 lab 参与产物合成。
- `autoFactory`：选择工厂任务（自定义 + fallback 链路），写入 `factoryProduct/factoryAmount`。
- `FactoryWork`：校验等级与原料后 `factory.produce(...)`。
- `autoPower`：按能量/Power 阈值自动开关 `powerSpawn`。
- `PowerSpawnWork`：在开关开启且资源满足时执行 `processPower()`。

## 关键机制
1. 可用量口径统一：自动任务决策会把 `storage/terminal + 结构内库存` 一并计算，避免误判缺料。
2. 等待窗口：缺料时不会立即清任务，而是进入 `waitSince` 观察窗口，到期再回收。
3. 等级约束：Factory 任务会严格校验商品等级与工厂等级匹配。
4. Lab 保留位：A/B 基底位由 `labReservations` 统一管理，避免被 boost 逻辑冲突占用。

## 手动控制能力
- Console 可打开/关闭 `lab/factory/powerSpawn` 自动模式。
- 可手动写入指定产物与配额，自动模块只负责“达到目标前持续运行”。
- 手动模式下（如 `powerSpawnMode=manual`）自动开关逻辑会退让。

## 当前实现边界
- 任务选择是启发式，不做全局利润优化。
- 多房间协同依赖资源管理模块供料，不在本模块内直接做跨房调度。
