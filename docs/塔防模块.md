# Tower 塔防系统

## 基本信息
- 功能定位：在单 tick 内为塔群选择最优动作（攻击/治疗/维修），同时控制能量消耗。
- 设计模式：优先级责任链（敌人>NPC>友军治疗>维修）、集火决策（可击杀优先）、预算控制（修塔睡眠窗口）。
- 运行节奏：`TowerWork()` 每次房间执行时触发。
- 数据边界：目标缓存按房间存于运行时对象（不写 Memory）；维修节奏写 `room.memory.towerRepairSleep`。

## 动作优先级
1. `TowerAttackEnemy()`：优先攻击白名单外敌人，使用 `pickTowerFocusTarget` 选集火目标。
2. `TowerAttackNPC()`：若无主要敌人，处理 Invader/Source Keeper。
3. `TowerHealCreep()`：治疗友军与白名单单位，战斗单位优先。
4. `TowerTaskRepair()`：资源与防御状态允许时执行修复。

## 关键机制
- 伤害模型：支持距离衰减、`PWR_OPERATE_TOWER/PWR_DISRUPT_TOWER` 修正、tough 减伤、敌方治疗抵消。
- 目标粘性：打不穿目标时改为低频点射，避免持续空耗塔能。
- 修塔节流：按塔群能量比例与防御态动态休眠，避免防守期误耗。
- 维修目标来源：优先任务池 `repair`，否则按结构损伤评分自动选取。

## 与防御系统的关系
- 防御系统决定“是否处于战备、是否突破、守军编制”。
- 塔防系统负责“本 tick 具体开火/治疗/修理对象”。

## 当前实现边界
- 目标选择为启发式，不做完整战场搜索。
- 房间超大规模混战时，缓存刷新频率仍需结合 CPU 预算调优。
