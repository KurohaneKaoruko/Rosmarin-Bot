# 任务池功能

## 基本信息
- 功能定位：提供房间级任务编排中心，统一承接“生产、运输、采集、孵化、终端”等任务。
- 设计模式：仓储模式（`MissionPools` 统一存取）、优先级调度（`level` 越小优先）、轻量锁（`lock + bindCreep`）。
- 运行节奏：任务生成在 `MissionUpdate`，任务执行在各角色行为中，提交/回收通过 `MissionSubmit`。
- 数据边界：任务常驻 `Memory.RosmarinBot.MissionPools[roomName]`，按池类型分桶。

## 任务模型
- 标准字段：`id/type/level/data/lock/bindCreep`。
- 固定池类型：`transport/build/repair/terminal/spawn/mine/boost`。
- 特殊归并：`manage` 任务统一归入 `transport` 池；`power` 与 `deposit` 任务统一归入 `mine` 池。

## 关键机制
1. 初始化：`initMissionPool()` 保证池结构完整且剔除非法池名。
2. 选取：`getMissionFromPool()` 先比 `level`，同级再比距离（切比雪夫）。
3. 并发控制：领取后可 `lockMissionInPool()`，完成后 `submitMission()` 自动解锁并按条件删任务。
4. 去重：`checkSameMissionInPool()` 通过 `type + data` 关键字段比对避免重复任务。
5. 缓存失效：任何 spawn 任务增删都会清空 `_spawnMissionNumCache`，保证孵化统计实时。

## 与业务模块的协作
- `MissionGet`：封装各类型任务的领取与有效性校验（无效即删并重取）。
- `MissionSubmit`：封装提交语义（如运输扣减、孵化任务一次性删除、批量撤销某角色孵化）。
- 结构控制/角色行为：只关心“拿任务/做任务/提任务”，不直接操作底层任务数组。

## 当前实现边界
- 锁机制是内存级轻锁，不含分布式抢占。
- 去重依赖 `data` 浅比较规则，复杂对象需调用方自行约束。
