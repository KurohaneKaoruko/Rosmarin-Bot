# 冲级分段监控

rush 模式的分段目标计时与判废机制。实现：`src/modules/shared/rushProgress.ts`（评估）、`src/prototype/Room/feature/raceVisual.ts`（逐 tick 采集与渲染）、`src/modules/infra/diagDump.ts`（落盘）。

## 段表口径

- 常量位置：`Thresholds.RUSH.SEGMENT_TARGETS`（目标等级 → `{ achieve 达成线, pass 合格线 }`，耗时相对 lv1 基线，单位 tick）。
- 现行目标（双档）：

| 段 | 达成线 | 合格线 |
|---|---|---|
| lv2 | 500t | 1kt |
| lv3 | 3kt | 5kt |
| lv4 | 10kt | —（达成线即判废线） |
| lv5 | 20kt | — |
| lv6 | 40kt | — |

- 计时基线：房间 lv1 落地时刻（`Memory.rooms.<房名>.race.baseline`），所有段耗时均为相对该基线的值。
- 分档规则：耗时 ≤ 达成线 = **达成**（绿）；达成线 ~ 合格线之间 = **合格**（黄，`behind` 标记）；> 合格线（无合格线段即达成线）= **判废**（红，attempt 失败）。进行中段的预计达成（ETA）超过达成线即亮落后告警。

## 面板字段（rush 模式左下角逐 tick 渲染）

分段目标区（每段一行）：

| 字段 | 含义 |
|---|---|
| `lv<n> ≤<达成线>/<合格线>` | 段目标等级与线位（有独立合格线的段双线并示，顺序为 达成/合格） |
| `达成 <耗时>` | 耗时 ≤ 达成线（绿） |
| `合格 <耗时>` | 达成线 ~ 合格线之间（黄） |
| `已<耗时> ETA <预计>` | 段进行中：已流逝耗时与预计达成耗时（已流逝 + 剩余进度点 / 实测速率） |
| `落后` / `判废` | 落后/判废标记（黄 / 红；达成=绿） |

另有 `attempt 判废 lv<n> 超段` 汇总行；清号（等级低于历史最高，账号重开）时全部分段状态与判废记录一并重置。

## 落盘字段

- `Memory.__raceDump`：race 内存整体序列化（每 30t），含 `baseline`、`levels`（逐级达成绝对 tick）、`levelRates`（段速）、`segments`（各段评估状态：`achievedAt`/`elapsed`/`eta`/`behind`/`failed`）、`failed`、`failedSegment`、`failSnapshot`（判废归因快照）。外部采集脚本无需修改即可读取。
- `Memory.__wd`：`race` 字段摘要（`baseline`/`levels`/`segments`/`failed`/`failedSegment`）。

## 判废规则与归因快照

- 达成段：达成耗时 > 目标×FAIL_RATIO → 判废。
- 未达成段：已流逝耗时 > 目标×FAIL_RATIO → 判废（即使立刻达成也已超时）。
- 首个判废段触发落账：`failed = true`、`failedSegment = 段等级`、`failSnapshot` 仅在首次判废时采集一次（后续段再判废不覆盖）。
- 归因快照内容：时刻、等级、判废段与目标/已耗时、能量状态、building 态、升级饥饿计数、在场升级火力（WORK 数）、creep 分角色 census、孵化池角色分布、控制器缓冲存量。
