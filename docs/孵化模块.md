# Spawn 孵化系统

## 基本信息
- 功能定位：根据房间状态动态生成孵化任务，并在可用 spawn 上执行孵化与故障兜底。
- 设计模式：策略表驱动（`RoleSpawnCheck` 按角色判定）、任务池解耦（生成端与执行端分离）、降级容错（缩体型与 universal 兜底）。
- 运行节奏：任务生成在 `UpdateSpawnMission()`；执行在 `SpawnWork()->SpawnCreep()`。
- 数据边界：孵化任务存于 `missionPools.spawn`；每 tick 统计缓存 `_spawnMissionNumCache`。

## 生成端（SpawnMission）
1. 收集当前 creep 数与排队任务数。
2. 按角色策略检查缺口（harvester/transport/worker 等）。
3. 满足条件则写入 spawn 任务（`SpawnMissionAdd`）。
4. 跨模块角色（Expand/Team/Defense/OutMine）也通过同一接口注入任务。

## worker / upgrader 与升级分工
- `upgrader` 为专人升级工：编制由 `modules/shared/roomWorkforce.getUpgraderTarget` 按
  「升级 work 预算（`getUpgradeWorkTarget`，含采集收入 × 能量水平 + 盈余/地面堆积项）÷ 每只 WORK 部件数」折算，
  再受**控制器/冲级工位**与**按 RCL 的人口上限**（`UPGRADER_POP_CAP_BY_LEVEL`）双重约束。
  人口上限专治低 RCL：能量容量撑不起大体型时 `GetRoleBodys` 会退到 1 WORK 的体型，
  同一笔 work 预算会被折成几十只（线上 RCL3 冲级房实测 38 只），把房间能量吸干。
- `worker` 定编 = 建造侧 + 刷墙保底；运行时按「建造配额 → 配额外专职升级」职责切分（`UPGRADE_SLOT_ROLES = ['worker', 'upgrader']` 两族共用升级工位名册）。
- 冲级编队（`up-upgrade`，旗帜 `房间/UP-UPGRADE/数量`）在场时，worker 的升级侧需求归零，升级吞吐完全交给编队。
- 地面掉落能量堆积（>1000/3000）时 worker 总人口临时突破硬上限加班消化，carrier 亦按堆积小幅加编；carrier 基础定编回归 `RoleLevelData` 标准表。

## 执行端（SpawnControl）
1. 挑选空闲 spawn（含激活状态判断）。
2. 从任务池取可执行任务，解析 body（固定体型或动态生成）。
3. 能量满足则直接孵化，成功后提交任务并更新角色计数。
4. 长期不足时触发两级兜底：
- 指定角色缩体型孵化（保基本运转）。
- 仍无法恢复时紧急孵化 `universal`（低级房止损）。

## 取任务口径与跨模块排队
- `getSpawnMission` 的排序键是 **task.level（越小越优先）**，同级按入队先后（FIFO）。
- 因此「谁先入队」与「谁 level 小」共同决定孵化顺序——跨模块补员必须显式设计这两个维度：
  - 外矿采集/搬运是**一条流水线**，强制同层排队（`OUTMINE_PIPELINE_LEVEL`），
    否则 `out-harvest=12 < out-carry=15` 会让采集工整体插队，搬运工被饿死在后面。
  - 外矿各目标房之间用**单房挂单上限 + 先近后远轮转**，防止单房独占 spawn。
    详见 `外矿采集模块.md` 的「补员派单」。

## 关键设计细节
- 低能量降级只对白名单角色生效，避免错误降级战术角色。
- `energyState` 与 `mode` 共同影响孵化目标数量与体型预算。
- spawn 任务增删会触发计数缓存失效，避免统计滞后。

## 当前实现边界
- 角色策略权重仍为经验规则，不是全局最优调度器。
- 多 spawn 并发场景按当前实现仍偏顺序分配，可继续优化吞吐。
