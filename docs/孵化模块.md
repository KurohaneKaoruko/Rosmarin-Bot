# Spawn 孵化系统

## 基本信息
- 功能定位：根据房间状态动态生成孵化任务，并在可用 spawn 上执行孵化与故障兜底。
- 设计模式：策略表驱动（`RoleSpawnCheck` 按角色判定）、任务池解耦（生成端与执行端分离）、降级容错（缩体型与 universal 兜底）。
- 运行节奏：任务生成在 `UpdateSpawnMission()`；执行在 `SpawnWork()->SpawnCreep()`。
- 数据边界：孵化任务存于 `missionPools.spawn`；每 tick 统计缓存 `_spawnMissionNumCache`。

## 生成端（SpawnMission）
1. 收集当前 creep 数与排队任务数。
2. 按角色策略检查缺口（harvester/transport/worker 等）。
3. 满足条件则写入 spawn 任务（`SpawnMissionAdd`）。
4. 跨模块角色（Expand/Team/Defense/OutMine）也通过同一接口注入任务。

## worker 与升级分工
- 常规升级已并入 worker：孵化目标 = max(建造目标, 升级目标, 刷墙保底)，运行时由 worker 动作优先级（build > repair > wall > upgrade）动态分配实际工作。
- 升级目标以 `RoleLevelData['upgrader']` 数量表为基准，按当前 worker 体型 work 数折算，并沿用控制器工位上限、storage 富余扩编、能量状态与基建优先等原有门槛。
- 冲级编队（`up-upgrade`，旗帜 `房间/UP-UPGRADE/数量`）在场时，worker 的升级侧需求归零，升级吞吐完全交给编队，避免两套升级人口互相挤占孵化队列。
- 存量 `upgrader` creep 通过 `RoleData.upgrader.executor = 'worker'` 无缝转按 worker 执行，不再孵化新个体。

## 执行端（SpawnControl）
1. 挑选空闲 spawn（含激活状态判断）。
2. 从任务池取可执行任务，解析 body（固定体型或动态生成）。
3. 能量满足则直接孵化，成功后提交任务并更新角色计数。
4. 长期不足时触发两级兜底：
- 指定角色缩体型孵化（保基本运转）。
- 仍无法恢复时紧急孵化 `universal`（低级房止损）。

## 关键设计细节
- 低能量降级只对白名单角色生效，避免错误降级战术角色。
- `energyState` 与 `mode` 共同影响孵化目标数量与体型预算。
- spawn 任务增删会触发计数缓存失效，避免统计滞后。

## 当前实现边界
- 角色策略权重仍为经验规则，不是全局最优调度器。
- 多 spawn 并发场景按当前实现仍偏顺序分配，可继续优化吞吐。
