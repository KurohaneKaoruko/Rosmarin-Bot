# 行为重构计划（Creep Action）

## 范围
- `src/prototype/Creep/action/**` 目录内全部 creep 行为脚本
- 新增 `src/framework/ai/**` 行为框架

## 约束与前置
- 不新增外部依赖
- 保持现有行为语义不变（除非发现明确 bug）
- 所有状态迁移必须通过显式事件触发
- 代码新增部分需配套中文注释

## 验证现状
- `npm run test` 目前存在既有失败（与本次重构无直接关联的缺失常量/文件）
- 在此基础上补充迁移，并记录未通过的测试项

## 清理/重构步骤
1. **框架落地**
   - 多层状态机框架（Layered FSM）
   - 行为树框架（含热插拔）
   - 策略模式容器（DI 注册）
   - 函数式管道（Effect 容器）
2. **状态机迁移**
   - 既有 source/target 或 action 状态机迁移到 Layered FSM
   - 显式事件常量与迁移常量统一声明
3. **非状态机重构**
   - 逐脚本评估：行为树 / 策略模式 / 函数式管道
   - 选型后改造为对应框架入口
4. **格式与注释**
   - 统一 `execute.ts` / `CreepConstant.ts` 的格式
   - 新增/迁移代码补充详细中文注释
5. **验证与回收**
   - 运行测试（记录已存在失败）
   - 汇总修改文件与风险点

## 本轮清理目标（继续）
- **状态机迁移补完**：剩余 work/采集/建造类脚本迁移至多层 FSM（显式事件 + 常量声明）
- **非状态机重构补完**：战斗类 -> 行为树；任务类 -> 策略模式；通用流程类 -> 函数式管道
- **兼容性移除**：删除旧的 `source/target/action` 等历史入口，统一走新框架
- **测试适配**：同步更新依赖旧入口的测试用例
- **注释强化**：所有新增/迁移逻辑补充详细中文注释

## 清理 pass 顺序（按气味）
1. **Boundary Violation**：拆解单个脚本内跨职责逻辑，放入对应框架层
2. **Dead Code**：删除已废弃的 `source/target/action` 入口与无效分支
3. **Needless Abstraction**：清理旧的状态字段/分支写法，统一事件驱动
4. **Duplication**：抽离共用决策函数，避免重复条件判断
5. **Test Reinforcement**：每轮改造后运行测试，记录基线失败项

## 气味分类（本轮关注）
- **Boundary Violation**：混合移动/采集/战斗/建造职责
- **Dead Code**：旧 `source/target` 入口、旧 `action` 状态分支
- **Needless Abstraction**：单次封装、传透式 helper
- **Duplication**：不同脚本重复条件判断与流程分支

## 评估规则（选型）
- **行为树**：高响应、战斗/防御/多分支决策
- **策略模式**：可替换算法族、线性流程
- **函数式管道**：决策与副作用分离、状态清晰
