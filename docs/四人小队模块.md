# Team 功能

## 基本信息
- 功能定位：提供四人小队（及变体）从“指令旗帜→排队孵化→集结编队→战斗执行”的完整链路。
- 设计模式：生产者-消费者队列（每房 TeamSpawnQueue）、状态机（`ready/attack/flee/avoid/sleep`）、运行时编排器（Spawner 与 Controller 分层）。
- 运行节奏：`TeamModule.start` 运行 `TeamSpawner`；`TeamModule.tick` 运行 `TeamController`。
- 数据边界：主数据在 `Memory.RosmarinBot.TeamData` 与 `Memory.RosmarinBot.TeamSpawnQueue`。

## Spawner（生成端）
1. 扫描旗帜：
- `TEAM_...`：孵化指令旗。
- `Team-xxxx`：已生成小队标记旗（数据不存在则清理）。
2. 校验并入队：按房间分桶排队，避免同房并发压垮孵化/boost。
3. 出队派发：生成 `teamID`，创建 TeamData，写 boost 任务，注入 spawn 任务。
4. 锁与超时：`active` 锁防重入；超时自动释放并短期忽略该队，防止死锁抖动。

## Controller（执行端）
1. 先处理 team creep：
- 完成 boost。
- 首次归队写入 TeamData.creeps。
- 失去队伍归属则自杀清理。
2. 再处理 team：
- `ready` 阶段等待满员并排序。
- 满员切换到 `attack` 执行 `Team.exec()`。
- 全灭解散；孤立 healer 会尝试补配给未满编队伍。

## 关键设计细节
- 同房串行派发：每个房间同一时刻只维护一个 active 组队任务。
- 双重去重：旗帜有 queued 标记，队列和 active 都会再校验一次。
- 失败回收：配置不存在、资源不足、房间不归属都会清理旗帜/内存残留。

## 当前实现边界
- 主要面向旗帜驱动流程，非旗帜指令链路覆盖较少。
- 队列锁超时是固定阈值，极端长链路场景可能仍需调参。
